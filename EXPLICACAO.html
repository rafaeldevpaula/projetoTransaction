Explicacao do projeto: analise paralela de transacoes financeiras

Disciplina: Programacao Paralela e Distribuida

1. Objetivo

O projeto analisa transacoes financeiras sinteticas e compara tres formas de processamento: sequencial, paralelo com ExecutorService e paralelo com tentativa de afinidade de processador.

2. Estrutura dos arquivos

Transaction.javaRepresenta uma transacao usando um record. TransactionGenerator.javaCria dados sinteticos reproduziveis. AnalysisResult.javaCalcula agregacoes, suspeitas e categorias. CategoryStats.javaArmazena estatisticas de cada categoria. Analyzer.javaContem as analises sequencial e paralela. AffinitySupport.javaTenta associar uma tarefa a uma CPU. Main.javaExecuta benchmarks e gera os resultados. .vscode/Configura compilacao e execucao sem Maven.

3. Modelo da transacao

Cada objeto Transaction possui id, cliente, data, valor, categoria, cidade, estado, tipo, estabelecimento e metodo de pagamento. O vetor e criado em memoria para que todas as abordagens processem os mesmos dados.

4. Geracao dos dados

O gerador usa uma semente fixa, garantindo testes reproduziveis. Os valores alternam entre quatro distribuicoes: uniforme, normal, exponencial e concentrada. Algumas transacoes recebem valores altos para testar a regra de suspeita.

5. Analise sequencial

Analyzer.sequential percorre o vetor uma vez. Para cada transacao, AnalysisResult.accept atualiza soma, quantidade, extremos, suspeitas e o mapa da categoria.

Uma transacao e suspeita quando possui valor acima de 10.000 ou quando possui valor acima de 5.000 e categoria Eletronicos.

Além das análises exigidas, o sistema calcula estatísticas por tipo de transação, por método de pagamento e por cidade. Para cada grupo são mostrados quantidade, valor total, valor médio e maior valor.

6. Paralelismo de dados

O vetor e dividido em blocos contiguos. Cada tarefa recebe uma faixa diferente e executa o mesmo algoritmo. O programa cria uma tarefa por bloco, e nao uma thread por transacao.

Cada tarefa retorna um AnalysisResult. Ao final, os resultados parciais sao combinados com merge. Essa etapa e a reducao dos resultados paralelos.

7. ExecutorService

Analyzer.parallel cria um executor com um numero fixo de threads. Cada bloco e enviado como Callable<AnalysisResult>, e cada Future representa o resultado que sera obtido depois.

O executor e encerrado no bloco finally, liberando as threads mesmo quando ocorre uma excecao.

8. Afinidade de processador

Quando o modo de afinidade esta ativo, cada tarefa recebe o indice da CPU correspondente. AffinitySupport procura a API OpenHFT por reflexao. Sem a biblioteca ou suporte nativo, a analise continua funcionando, mas a afinidade nao e aplicada.

9. Benchmark

Main mede o tempo com System.nanoTime. Para cada quantidade de threads, executa os modos Executor e Executor com afinidade. Em seguida, verifica se a contagem e a soma coincidem com o resultado sequencial.

speedup = tempo_sequencial / tempo_paralelo
eficiencia = speedup / numero_de_threads

Speedup maior indica que a versao paralela foi mais rapida. Eficiencia mostra quanto do potencial das threads foi aproveitado.

10. Graficos

Ao final, Main cria resultados.html. O relatorio apresenta barras proporcionais para tempo, speedup e eficiencia, usando uma cor para cada modo. O arquivo pode ser aberto no navegador e usado para capturar imagens para o relatorio da disciplina.

11. Como interpretar os resultados

Valor total: soma dos valores de todas as transacoes. Ele deve ser igual na analise sequencial e nas analises paralelas.

Valor medio: valor total dividido pela quantidade de transacoes. Serve para observar o valor medio movimentado.

Transacoes suspeitas: quantidade de registros que obedecem a regra definida no projeto: valor acima de 10.000 ou valor acima de 5.000 na categoria Eletronicos.

Estatisticas por categoria: mostram quantidade, total, media e maior transacao de Alimentacao, Transporte, Eletronicos, Saude e Educacao.

Analises extras: o relatorio tambem organiza os mesmos dados por tipo de transacao, metodo de pagamento e cidade.

Tempo (ms): tempo gasto para analisar os dados. Uma barra menor representa uma execucao mais rapida.

Speedup: compara o tempo sequencial com o tempo paralelo. Por exemplo, speedup 2 significa que a execucao paralela foi aproximadamente duas vezes mais rapida.

Eficiencia: mostra o aproveitamento das threads. Ela e calculada dividindo o speedup pela quantidade de threads. Quanto mais proxima de 1, melhor o aproveitamento.

Resultado OK: indica que a analise paralela produziu a mesma quantidade de transacoes e o mesmo total da analise sequencial.

12. Como executar

No VS Code, abra Run and Debug e selecione Executar analise de transacoes.

New-Item -ItemType Directory -Force out | Out-Null
javac --release 25 -d out (Get-ChildItem -Recurse src/main/java -Filter *.java).FullName
java -cp out app.Main --quantidade=100000 --threads=1,2,4,8

Depois, abra resultados.html no navegador.

13. Conclusao

O projeto demonstra paralelismo de dados porque varias tarefas executam o mesmo algoritmo sobre partes diferentes do vetor. A comparacao dos tempos permite discutir overhead, balanceamento, quantidade de nucleos, speedup, eficiencia e efeito da afinidade de processador.
